TensorHawk Rust · Apache-2.0

Static security analysis for AI model artifacts — know what's inside before you load it. A fully offline analyzer that inspects model files, configs, and datasets for supply-chain risks.

GitHub Latest release
AI Security Static Analysis Supply Chain SARIF Offline

Overview

TensorHawk is a fully offline static analyzer designed to inspect AI model artifacts before loading them. It addresses a critical supply-chain weakness: loading PyTorch checkpoints with torch.load executes pickle opcodes before inference ever runs, which can enable code execution, credential theft, and data leakage.

It examines bytes and structure — never runtime behavior — and surfaces specific, evidenced findings rather than claiming a file is "safe". Secret and PII patterns prioritize precision over recall, and every finding carries a confidence score.

Core capabilities

Nine independent scanners run over each artifact:

1 Pickle

Dangerous imports (os, subprocess, ctypes) and REDUCE-based code execution.

2 Secrets

API keys (AWS, GitHub, Slack, Google, Stripe, OpenAI, Anthropic), private keys, JWTs, DB credentials.

3 PII

Emails, Luhn-validated credit cards, SSN, Aadhaar, PAN, IBAN in metadata.

4 Metadata

Build paths, internal URLs, cloud identifiers, and provenance leaks.

5 Config

Custom-code execution in Hugging Face configs (auto_map, trust_remote_code).

6 Dataset

CSV/TSV/JSONL analysis for PII, prompt injection, data poisoning, hidden Unicode.

7 Entropy

High-entropy payloads hidden in pickle object graphs.

8 Weights

Shape/dtype mismatches, NaN/Inf values, zeroed tensors, overflow anomalies.

9 Lineage

LoRA/PEFT adapters, base models, and quantization ancestry.

Usage

Basic scanning

tensorhawk model.safetensors
tensorhawk ./models --recursive --fail-on high
tensorhawk ~/.ollama/models/blobs/ --recursive
tensorhawk training_data.csv

Output formats

tensorhawk model.bin --format json > report.json
tensorhawk model.bin --format sarif > report.sarif
tensorhawk ./models --recursive --format html --output report.html
tensorhawk ./models --recursive --format pdf --output report.pdf --author <name>

Advanced options

tensorhawk model.bin --min-severity medium
tensorhawk model.onnx --rules ./my-rules
tensorhawk ./models --recursive --write-baseline tensorhawk.baseline.json
tensorhawk ./models --recursive --baseline tensorhawk.baseline.json
tensorhawk model.safetensors --experimental

Output & scoring

Findings are scored 0–100 and mapped to the OWASP LLM Top 10, MITRE ATLAS, and CWE frameworks. Five output formats are available:

  • Human-readable — formatted terminal output with severity levels
  • JSON — machine-readable structured findings
  • SARIF — for GitHub code-scanning integration
  • HTML — professional security-assessment reports
  • PDF — branded, paginated reports with author attribution

Exit codes

CodeMeaning
0Completed; no findings at/above threshold
1Completed; a finding at/above threshold was detected
2No scannable artifact found

CI integration

Emit SARIF and fail the build on high-severity findings, then upload to GitHub code scanning:

- name: Scan model artifacts
  run: |
    tensorhawk ./models --recursive --format sarif --output tensorhawk.sarif --fail-on high
- name: Upload to code scanning
  uses: github/codeql-action/upload-sarif@v3
  with:
    sarif_file: tensorhawk.sarif

Scope & limitations

TensorHawk is strictly a static analyzer: it examines bytes and structure, not runtime behavior. It cannot prove safety — only surface specific, evidenced risks. Backdoor detection remains an open research problem; experimental heuristics are clearly labeled probabilistic.

OT-ORCA Python · MIT

A passive network security toolkit for Operational Technology and Industrial Control System environments. It listens through tshark, reconstructs asset inventory and protocol interactions, applies rule-based detection, and generates severity-rated findings with remediation guidance.

GitHub Releases
OT / ICS Passive Modbus DNP3 IEC 62443 MITRE ATT&CK for ICS

Overview & design philosophy

OT-ORCA's fundamental principle is passivity: in its normal mode it transmits nothing onto the monitored network — it only reads frames. This prevents the crashes and faults that active scanning can trigger in PLCs, RTUs, and field devices common in industrial settings.

Passive mode observes traffic only. Active Nmap discovery is strictly opt-in (--active-nmap) and carries inherent risk of device faults despite gentle profile defaults.

Core features

  • Protocol coverage — 13+ industrial protocols: Modbus, DNP3, S7comm, EtherNet/IP, IEC-104, BACnet, OPC UA, PROFINET, IEC 61850, Omron FINS, HART-IP, MQTT, and EtherCAT.
  • Detection engine — 35 detections mapped to IEC 62443, NIST SP 800-82r3, MITRE ATT&CK for ICS, and CWE. Each finding includes severity, description, and mitigation steps.
  • Network visualization — auto-generated Purdue-model topology diagrams showing control flows in red, with Graphviz DOT export.
  • Analytics — asset inventory classification, protocol usage analysis, top-talkers identification, and polling-periodicity anomaly scoring (NumPy).
  • AI integration (optional) — Ollama, OpenAI-compatible endpoints, or MCP for executive summaries and remediation roadmaps, with a deterministic fallback.
  • Cross-platform GUI — pure Tkinter interface, no extra dependencies, on Windows, macOS, and Linux.
  • Reporting — self-contained HTML with embedded charts, JSON, and Markdown.

Prerequisite: Wireshark / tshark must be installed.

sudo apt install tshark python3-tk

macOS

brew install wireshark

From source

git clone https://github.com/0xsh4n/ot-orca ot-orca && cd ot-orca
python3 -m pip install -r requirements.txt

Precompiled standalone executables are available for Windows x64, Debian/Ubuntu/Kali, and a Linux x64 portable build on the Releases page.

Usage

List available interfaces

python3 -m otorca interfaces

Passive scan for 60 seconds

python3 -m otorca scan -i eth0 -d 60 -o plant-report.html

Analyze an existing capture

python3 -m otorca scan -r plant.pcapng -o report.html --json result.json

With AI analysis using local Ollama

python3 -m otorca scan -r plant.pcap --ai --ai-model qwen2.5 -o report.html

Launch the GUI

python3 -m otorca gui

GUI workspace

  • Capture — interface selection, BPF filtering, duration/packet limits, live counters
  • Findings — severity-colored vulnerability list with descriptions and mitigations
  • Assets — discovered device inventory with roles and protocol information
  • Topology — network diagram visualization
  • Report & AI — AI configuration, active-nmap option, export settings

AI & MCP integration

The optional AI analyst provides narrative synthesis, attacker-perspective analysis, and prioritized remediation. It transmits only finding metadata and counts — never raw secrets — and falls back to a deterministic engine when no backend is available.

Ollama (local, recommended)

ollama pull qwen2.5
python3 -m otorca scan -r plant.pcap --ai --ai-provider ollama --ai-model qwen2.5

OpenAI-compatible endpoints

python3 -m otorca scan -r plant.pcap --ai --ai-provider openai \
    --ai-url https://api.openai.com/v1 --ai-model gpt-4o-mini --ai-key $KEY

Legal & safety

OT-ORCA is for authorized assessment of networks you own or have explicit permission to test. Passive mode only observes traffic, but verifying monitoring authorization remains essential. Active Nmap scanning is opt-in and carries inherent risk of device faults despite gentle defaults.
