About

About 0xsh4n

Offensive security work, focused on how real applications actually break in production. These days that includes the new failure modes AI brings with it.

I'm an Associate Security Analyst working on web, API, and mobile application security. Day to day that means hands-on testing with Burp Suite and similar tooling, hunting for auth issues, broken access control, and messy business logic.

Lately a lot of that work touches AI and LLM systems. Prompt injection, RAG retrieval boundaries, agent tool abuse, and the ordinary web bugs sitting in the API around the model. Most teams haven't looked hard at it yet, so there's plenty to find.

I also pick up freelance work alongside my full-time job. Short VAPT projects, focused AppSec reviews, and mobile assessments when a team wants an extra set of offensive eyes.

When I'm not on an engagement I build small security tools and write up what I find. Recon helpers, AI model scanning, some automation around bounty workflows. A couple are live and free to use over in resources.

AI Security

Securing AI & LLM systems

The model is only part of the attack surface. I test the rest of the system too: retrieval, tools, output rendering, and the API around it. Findings map to the OWASP Top 10 for LLM Applications.

LLM application testing

  • Direct and indirect prompt injection, jailbreaks, and system-prompt leakage
  • Insecure output handling: markdown and HTML XSS, plus data exfil through rendered replies
  • Unbounded consumption and denial-of-wallet abuse
Prompt Injection Output Handling Jailbreaks

RAG & retrieval security

  • Cross-tenant document leakage and retrieval-boundary bypass
  • Indirect injection planted in ingested documents and pages
  • Vector / embedding weaknesses and knowledge-base poisoning
Retrieval Vector DB Data Poisoning

Agent & tool security

  • Excessive agency: unauthorized or cross-user tool actions
  • Tool-parameter injection that becomes IDOR or SSRF through the tool call
  • Confused-deputy issues, tool chaining, and permission scoping
Excessive Agency SSRF Tool Abuse

Model & supply-chain security

  • Malicious model files: pickle RCE in PyTorch, GGUF, and safetensors
  • Secrets and PII left inside model artifacts
  • Unsafe deserialization and dependency risk. It's what I built TensorHawk to catch.
Model Files Pickle RCE Supply Chain
